Authentication

The documentation portal uses OAuth 2.0 against Nimbus Accounts. This page documents the sign-in endpoints the portal exposes and how portal sessions are carried.

Sign-in endpoints

EndpointMethodPurpose
/oauth2authorizeGET Starts the flow and redirects to the Nimbus Accounts consent screen. Takes an optional return_url.
/oauth2callbackGET Consent screen returns here with state and code. The portal exchanges the code for credentials.

Starting a flow needs no account:

curl -s -D headers.txt -o /dev/null \
  'http://localhost:13337/oauth2authorize?return_url=%2F'

Portal sessions

The portal is stateless. There is no server-side session store: everything the callback needs is carried in the session cookie, which is signed with the application's secret key so that clients cannot tamper with it.

Keys the portal places in the session:

KeyContents
google_oauth2_csrf_token Per-flow CSRF token. Must match csrf_token inside the state parameter handed back by the consent screen.
google_oauth2_flow_<csrf> The in-progress flow object, serialized. The callback reads it back out to perform the code exchange.
google_oauth2_credentials Credentials for the signed-in user, once the exchange succeeds.
Note: session keys carry the google_oauth2_ prefix because the portal uses the oauth2client Flask integration. The prefix has no bearing on which identity provider is configured.

Callback responses

ResponseCause
Invalid request Missing state, missing code, or no CSRF token in the session.
Invalid request state state unparseable, CSRF mismatch, or no stored flow for that token.
An error occurred: ... The code exchange was attempted and the identity provider rejected it.
302 to return_urlSign-in complete.

Configuration

Portal deployments read the following at start-up. Operators are asked to keep the number of distinct secrets low so that rotation stays manageable across the fleet.

SECRET_KEY                     # signs the session cookie
NIMBUS_OAUTH2_CLIENT_ID        # OAuth 2.0 client identifier
NIMBUS_OAUTH2_CLIENT_SECRET    # OAuth 2.0 client secret
